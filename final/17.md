# Bài 17: Tìm Số Nhỏ Nhất Chỉ Chứa 0,1 Chia Hết Cho N

## Đề Bài

Cho số nguyên dương **n**. Hãy tìm số nguyên dương **m** nhỏ nhất có không quá 9 chữ số thỏa mãn:
- **m** chỉ chứa các chữ số {0, 1}
- **m** là bội của **n** (m chia hết cho n)

**Dữ liệu vào:**
- Gồm một số nguyên dương $n$ ($n \leq 100$)

**Kết quả:**
- Gồm một số nguyên duy nhất là **m**

**Ví dụ:**
```
INPUT:
6

OUTPUT:
1110
```

---

## Phân Tích Bài Toán

### Hiểu Đề Bài

Tìm số nhỏ nhất chỉ gồm chữ số 0 và 1 mà chia hết cho n.

**Ví dụ:** n = 6

Các số chỉ chứa 0,1 theo thứ tự tăng dần:
```
1    % 6 = 1  ✗
10   % 6 = 4  ✗
11   % 6 = 5  ✗
100  % 6 = 4  ✗
101  % 6 = 5  ✗
110  % 6 = 2  ✗
111  % 6 = 3  ✗
1000 % 6 = 4  ✗
1001 % 6 = 5  ✗
1010 % 6 = 2  ✗
1011 % 6 = 3  ✗
1100 % 6 = 2  ✗
1101 % 6 = 3  ✗
1110 % 6 = 0  ✓
```

**Output:** 1110

### Nhận xét: Luôn có đáp án trong trường hợp tổng quát, nhưng với giới hạn 9 chữ số?

**Nguyên lý Dirichlet:**

Xét dãy: 1, 11, 111, 1111, 11111, ..., 111...1 (n+1 số 1)

- Có **n+1** số
- Mỗi số có phần dư khi chia cho n: {0, 1, 2, ..., n-1} (n giá trị)
- Theo Pigeonhole: **ít nhất 2 số có cùng phần dư** hoặc **có 1 số có phần dư = 0**

**Trường hợp 1:** Có số có phần dư = 0 -> Đáp án!

**Trường hợp 2:** Có 2 số a > b với $a \equiv b \pmod{n}$
- $(a - b) \equiv 0 \pmod{n}$
- $a - b$ có dạng 111...1000...0 (chỉ chứa 0,1)
- Đáp án!

-> **Luôn tồn tại đáp án!**

**Giới hạn 9 chữ số?**

- Không chắn chắn có đáp án với ràng buộc 9 chữ số của đề bài. Nguyên lý Dirichlet không đảm bảo điều đó.
- Với n≤100, độ dài nghiệm có thể lên đến 100 chữ số, vượt xa 9 chữ số.

## Approach 1: Brute Force - Sinh Tất Cả

### Ý Tưởng

**Quan sát then chốt:**

Số chỉ chứa chữ số {0, 1} giống như số nhị phân, chỉ khác là đọc như số thập phân!

**Ví dụ minh họa:**
```
Binary (cơ số 2)  ->  Đọc như thập phân
      1           ->        1
     10           ->       10
     11           ->       11
    100           ->      100
    101           ->      101
    110           ->      110
    111           ->      111
   1000           ->     1000
```

**Cách tiếp cận:**

**Bước 1: Liệt kê tất cả số chỉ chứa {0,1}**
- Dùng số nguyên `i` từ 1 đến $2^9 - 1$ (vì giới hạn 9 chữ số)
- Chuyển `i` sang biểu diễn nhị phân
- Đọc biểu diễn nhị phân như số thập phân

**Ví dụ chi tiết:**
```
i = 5 (thập phân)
-> Binary: 101
-> Đọc như số: 101 (một trăm linh một)

i = 13
-> Binary: 1101
-> Đọc như số: 1101 (một nghìn một trăm linh một)
```

**Thuật toán chuyển đổi:**
```
binaryToDecimal01(num):
    result = 0
    multiplier = 1  // Vị trí: đơn vị, chục, trăm,...
    
    while num > 0:
        bit = num % 2        // Lấy bit cuối
        result += bit × multiplier
        multiplier ×= 10     // Tăng bậc
        num /= 2             // Bỏ bit cuối
    
    return result
```

**Ví dụ chạy:**
```
Input: num = 5 (binary: 101)

Lần 1: bit=1, result=1×1=1, multiplier=10, num=2
Lần 2: bit=0, result=1+0×10=1, multiplier=100, num=1
Lần 3: bit=1, result=1+1×100=101, multiplier=1000, num=0

Output: 101
```

**Bước 2: Kiểm tra điều kiện chia hết**
- Với mỗi số sinh ra, kiểm tra: `num % n == 0`
- Nếu đúng, đây là đáp án!
- Vì duyệt theo thứ tự tăng dần, số đầu tiên tìm thấy là nhỏ nhất

**Tại sao approach này hoạt động?**
- Đơn giản, dễ hiểu
- Đảm bảo không bỏ sót (duyệt tất cả)
- Tìm số nhỏ nhất (duyệt theo thứ tự)

**Giới hạn:**
- Chỉ sinh được số ≤ 9 chữ số (111111111)
- Với $n$ lớn, có thể không tìm thấy trong phạm vi này
- Nhưng theo Pigeonhole Principle, luôn tồn tại đáp án ≤ $n$ chữ số

### Code Implementation

```cpp
#include <iostream>
#include <string>
using namespace std;

// Chuyển số nhị phân thành số thập phân chỉ chứa chữ số 0,1
// Ví dụ: 5 (binary: 101) -> 101 (thập phân)
// Time: O(log num) ≈ O(k) với k là số bit
long long binaryToDecimal01(int num) {
    long long result = 0;      // Số kết quả
    long long multiplier = 1;   // Vị trí: 1, 10, 100, 1000,...
    
    // Xử lý từng bit từ phải sang trái
    while (num > 0) {
        int bit = num % 2;           // Lấy bit cuối cùng (0 hoặc 1)
        result += bit * multiplier;  // Thêm vào kết quả
        multiplier *= 10;            // Tăng bậc: 1 -> 10 -> 100...
        num /= 2;                    // Bỏ bit cuối (shift right)
    }
    
    return result;
}

// Brute Force: Sinh tất cả số chỉ chứa {0,1} theo thứ tự tăng dần
// Time: O(2^k × k) với k = 9 -> O(512 × 9) = O(4608)
string bruteForceSolution(int n) {
    // Duyệt từ 1 đến 2^9 - 1 = 511
    // Vì giới hạn độ dài tối đa 9 chữ số (111111111)
    for (int i = 1; i < (1 << 9); i++) {  // 1 << 9 = 2^9 = 512
        // Chuyển i (nhị phân) sang số chỉ chứa {0,1}
        long long num = binaryToDecimal01(i);
        
        // Kiểm tra chia hết cho n
        if (num % n == 0) {
            return to_string(num);  // Tìm thấy! Đây là số nhỏ nhất
        }
    }
    
    // Không tìm thấy trong phạm vi (theo đề, luôn tồn tại)
    return "-1";
}

int main() {
    int n;
    cin >> n;  // Nhập số n cần chia hết
    
    string result = bruteForceSolution(n);
    cout << result << endl;  // In số nhỏ nhất tìm được
    
    return 0;
}
```

### Phân Tích Độ Phức Tạp

**Time Complexity:** $O(2^k \times k)$

- k = 9 (số chữ số tối đa)
- $2^9 = 512$ số cần kiểm tra
- Mỗi số: chuyển đổi và kiểm tra $O(k)$

**Space Complexity:** $O(1)$

### Đánh Giá

Với k = 9:
- $O(512 \times 9) \approx 4600$ operations
- **Chấp nhận được!**

**Vấn đề:**
- Số có thể rất lớn (111111111 ≈ $10^9$)
- Cần dùng `long long` để tránh overflow

## Approach 2: BFS - Tối Ưu

### Ý Tưởng

**Vấn đề của Brute Force:**

Làm việc với số thực rất lớn (111111111 ≈ $10^9$), có thể overflow và chậm.

**Key Insight - Modular Arithmetic:**

**Quan sát then chốt:** Chúng ta chỉ quan tâm số $m$ có chia hết cho $n$ hay không, tức là $m \bmod n = 0$.

-> **Không cần lưu toàn bộ số $m$, chỉ cần lưu phần dư $m \bmod n$!**

**Tại sao hiệu quả?**
- Phần dư chỉ có $n$ giá trị khác nhau: $\{0, 1, 2, \ldots, n-1\}$
- Với $n \leq 100$, chỉ cần theo dõi tối đa 100 trạng thái!
- Theo Pigeonhole Principle, chắc chắn gặp phần dư = 0 trong $n$ bước

**Mô hình hoá bằng BFS:**

**State:** `(remainder, number_string)`
- `remainder`: Phần dư hiện tại khi chia cho $n$
- `number_string`: Chuỗi biểu diễn số (cho output)

**Initial state:** `(1 % n, "1")`
- Bắt đầu từ số 1 (số nhỏ nhất chỉ chứa chữ số 1)

**Transitions (sinh số mới):**

Từ trạng thái `(r, s)`, có 2 cách mở rộng:

1. **Thêm '0' vào cuối:**
   - Số mới: $s \times 10$ (shift trái)
   - Phần dư mới: `(r × 10) % n`
   - State mới: `((r × 10) % n, s + "0")`

2. **Thêm '1' vào cuối:**
   - Số mới: $s \times 10 + 1$
   - Phần dư mới: `(r × 10 + 1) % n`
   - State mới: `((r × 10 + 1) % n, s + "1")`

**Ví dụ cụ thể với n=6:**
```
Bắt đầu: (1, "1")

Thêm '0': (1×10) % 6 = 10 % 6 = 4 -> (4, "10")
Thêm '1': (1×10+1) % 6 = 11 % 6 = 5 -> (5, "11")

Từ (4, "10"):
  Thêm '0': (4×10) % 6 = 4 -> (4, "100") - đã thăm
  Thêm '1': (4×10+1) % 6 = 5 -> (5, "101") - đã thăm

Từ (5, "11"):
  Thêm '0': (5×10) % 6 = 2 -> (2, "110")
  Thêm '1': (5×10+1) % 6 = 3 -> (3, "111")

Từ (2, "110"):
  Thêm '0': (2×10) % 6 = 2 - đã thăm
  Thêm '1': (2×10+1) % 6 = 3 - đã thăm

Từ (3, "111"):
  Thêm '0': (3×10) % 6 = 0 -> (0, "1110") ← TÌM THẤY!
```

**Goal state:** `remainder = 0`

**Visited tracking:** Đánh dấu `visited[remainder]` để tránh lặp
- Mỗi remainder chỉ cần thăm 1 lần
- Nếu gặp lại remainder đã thăm -> skip (số dài hơn, không tốt hơn)

**Tại sao BFS tối ưu?**
- **Tìm số nhỏ nhất:** BFS duyệt theo level -> số tìm được đầu tiên là ngắn nhất
- **Không lãng phí:** Visited array đảm bảo mỗi remainder chỉ xử lý 1 lần
- **Độ phức tạp tuyến tính:** $O(n)$ states, mỗi state $O(1)$

**So sánh với Brute Force:**
| | Brute Force | BFS |
|---|---|---|
| Số state | $2^9 = 512$ | $\leq n \leq 100$ |
| Lưu trữ | Số lớn ($10^9$) | Chỉ remainder ($<100$) |
| Độ phức tạp | $O(2^k)$ | $O(n)$ |
| Kết quả | Đúng | Đúng và nhanh hơn |

### BFS State

**State:** `(remainder, number_string)`
- `remainder`: $m \bmod n$
- `number_string`: chuỗi biểu diễn số m

**Start State:** $(1 \bmod n, \text{"1"})$

**Transition:**
- Từ state $(r, s)$, sinh 2 state mới:
  - Thêm '0': $((r \times 10) \bmod n, s + \text{"0"})$
  - Thêm '1': $((r \times 10 + 1) \bmod n, s + \text{"1"})$

**Goal State:** $remainder = 0$

**Visited:** Đánh dấu các remainder đã thăm để tránh lặp

### Visualization

**Example:** n = 6

```
Level 0:  (1, "1")
          ↙     ↘
Level 1: (4, "10")  (5, "11")
          ↙   ↘      ↙    ↘
Level 2: (4*) (5*)  (2, "110") (3, "111")
                     ↙   ↘        ↙   ↘
Level 3:          (2*) (0, "1110") (3*) (1*)

* = already visited
```

**Tìm thấy:** $(0, \text{"1110"})$ -> Output: 1110

### Code Implementation

**Tóm tắt:**
Hàm dùng **BFS trên phần dư modulo n** để tìm **số nhỏ nhất chỉ gồm 0 và 1** chia hết cho `n`: mỗi trạng thái là `(phần dư, chuỗi số)`, mỗi bước thêm `0` hoặc `1`.
Khi gặp phần dư `0` thì dừng, dùng `visited` để tránh lặp và giới hạn độ dài để kiểm soát không gian tìm kiếm.


```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <string>
using namespace std;

// BFS với Modular Arithmetic: Tìm số nhỏ nhất chỉ chứa {0,1} chia hết cho n
// Time: O(n), Space: O(n)
// Key Insight: Chỉ lưu phần dư (remainder) thay vì toàn bộ số
string bfsSolution(int n) {
    // Trường hợp đặc biệt: n = 1 -> kết quả là "1"
    if (n == 1) return "1";
    
    // Queue lưu: (phần dư hiện tại, chuỗi số tương ứng)
    queue<pair<int, string>> q;
    
    // Visited array: đánh dấu phần dư đã thăm để tránh lặp
    vector<bool> visited(n, false);
    
    // Bắt đầu với số "1" (số nhỏ nhất chỉ chứa chữ số 1)
    q.push({1 % n, "1"});      // Phần dư của 1 khi chia cho n
    visited[1 % n] = true;     // Đánh dấu đã thăm
    
    // BFS: Duyệt theo level (số ngắn nhất trước)
    while (!q.empty()) {
        int remainder = q.front().first;    // Phần dư hiện tại
        string num_str = q.front().second;  // Chuỗi số tương ứng
        q.pop();
        
        // Kiểm tra xem đã chia hết chưa (phần dư = 0)
        if (remainder == 0) {
            return num_str;  // Tìm thấy! Đây là số nhỏ nhất
        }
        
        // Giới hạn độ dài: không quá 9 chữ số
        // (Theo Pigeonhole Principle, chắc chắn tìm thấy trong n bước)
        if (num_str.length() >= 9) continue;
        
        // Transition 1: Thêm '0' vào cuối
        // Số mới: num_str + "0" = num_str × 10
        // Phần dư mới: (remainder × 10) % n
        int new_remainder_0 = (remainder * 10) % n;
        if (!visited[new_remainder_0]) {
            visited[new_remainder_0] = true;           // Đánh dấu
            q.push({new_remainder_0, num_str + "0"}); // Thêm vào queue
        }
        
        // Transition 2: Thêm '1' vào cuối
        // Số mới: num_str + "1" = num_str × 10 + 1
        // Phần dư mới: (remainder × 10 + 1) % n
        int new_remainder_1 = (remainder * 10 + 1) % n;
        if (!visited[new_remainder_1]) {
            visited[new_remainder_1] = true;           // Đánh dấu
            q.push({new_remainder_1, num_str + "1"}); // Thêm vào queue
        }
    }
    
    // Không tìm thấy (theo lý thuyết, không xảy ra)
    return "-1";
}

int main() {
    int n;
    cin >> n;
    
    string result = bfsSolution(n);
    cout << result << endl;
    
    return 0;
}
```

### Phân Tích Độ Phức Tạp

**Time Complexity:** $O(n)$

- Tối đa n trạng thái (n phần dư khác nhau)
- Mỗi trạng thái xử lý $O(1)$

**Space Complexity:** $O(n)$

- Queue: $O(n)$
- Visited array: $O(n)$

### Đánh Giá

Với $n \leq 100$:
- $O(100)$ operations
- **Rất nhanh! Tối ưu!**

**So sánh với Brute Force:**
- Brute Force: $O(2^9) = 512$ (độc lập với n)
- BFS: $O(n) \leq 100$
- BFS **nhanh hơn và đảm bảo hơn**!

## Approach 3: Space Optimization

### Ý Tưởng

Thay vì lưu chuỗi trong queue (tốn space), lưu **parent pointers** để tái tạo chuỗi kết quả.

**Data structures:**
- `parent[r]`: remainder trước đó dẫn đến r
- `digit[r]`: chữ số (0 hoặc 1) đã thêm để đến r

**Reconstruct:**
1. Bắt đầu từ `remainder = 0`
2. Trace ngược qua `parent[]`
3. Lưu các `digit[]` và reverse

### Code Implementation

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

// BFS Tối ưu - Space Optimization: Dùng parent pointers thay vì lưu strings
// Time: O(n), Space: O(n) nhưng tiết kiệm bộ nhớ hơn
// Không lưu chuỗi dài trong queue, chỉ lưu remainder (integer)
string bfsOptimized(int n) {
    // Trường hợp đặc biệt
    if (n == 1) return "1";
    
    queue<int> q;                // Chỉ lưu remainder (không lưu string)
    vector<bool> visited(n, false);  // Đánh dấu đã thăm
    vector<int> parent(n, -1);       // Lưu remainder cha
    vector<int> digit(n, -1);        // Lưu chữ số thêm (0 hoặc 1)
    
    // Bắt đầu từ số "1"
    q.push(1 % n);
    visited[1 % n] = true;
    // parent và digit của node gốc giữ nguyên -1
    
    while (!q.empty()) {
        int remainder = q.front();
        q.pop();
        
        // Kiểm tra đích (phần dư = 0 -> chia hết)
        if (remainder == 0) {
            // Reconstruct đường đi từ 0 ngược về gốc
            string result = "";
            int current = 0;  // Bắt đầu từ remainder = 0
            
            // Trace back theo parent pointers
            while (parent[current] != -1) {
                result += (char)('0' + digit[current]);  // Thêm chữ số (0 hoặc 1)
                current = parent[current];               // Lùi về cha
            }
            
            result += "1";  // Thêm chữ số đầu tiên (gốc)
            
            // Đảo ngược vì trace back từ cuối về đầu
            reverse(result.begin(), result.end());
            return result;
        }
        
        // Transition 1: Thêm '0'
        int new_r0 = (remainder * 10) % n;
        if (!visited[new_r0]) {
            visited[new_r0] = true;
            parent[new_r0] = remainder;  // Cha của new_r0 là remainder
            digit[new_r0] = 0;           // Chữ số thêm là '0'
            q.push(new_r0);
        }
        
        // Transition 2: Thêm '1'
        int new_r1 = (remainder * 10 + 1) % n;
        if (!visited[new_r1]) {
            visited[new_r1] = true;
            parent[new_r1] = remainder;  // Cha của new_r1 là remainder
            digit[new_r1] = 1;           // Chữ số thêm là '1'
            q.push(new_r1);
        }
    }
    
    // Không tìm thấy
    return "-1";
}

int main() {
    int n;
```

## Tổng Kết

### Quy Trình Giải Quyết

1. **Nhận dạng bài toán:** Number theory + Graph search
2. **Brute force:** Sinh tất cả số, kiểm tra từng cái
3. **Tối ưu với BFS:** Chỉ lưu phần dư, tìm kiếm theo graph
4. **Pigeonhole Principle:** Chứng minh luôn có đáp án
5. **Space optimization:** Parent pointers để reconstruct

### Key Points

- **Time:** $O(n)$ với BFS
- **Space:** $O(n)$
- **Modular arithmetic:** Chỉ cần lưu phần dư, không cần số thật

### Câu Hỏi Mở Rộng Có Thể Gặp

**Q: Nếu cho phép chữ số {0, 1, 2}?**
- A: Tương tự BFS, mỗi state sinh 3 state mới. Complexity vẫn O(n).

**Q: Nếu n rất lớn (10^6)?**
- A: BFS vẫn O(n), nhưng space O(n) có thể lớn. Có thể dùng iterative deepening hoặc optimization khác.

**Q: Tại sao không dùng DFS?**
- A: BFS đảm bảo tìm số **nhỏ nhất** (level by level). DFS có thể tìm số dài hơn.

**Q: Nếu không giới hạn 9 chữ số?**
- A: Vẫn áp dụng BFS. Theo nguyên lý Dirichlet, chắc chắn tìm thấy trong n bước, nên số chữ số ≤ n.

**Q: Bài toán liên quan?**
- A: Modular arithmetic problems, BFS on implicit graphs, Number theory - divisibility
