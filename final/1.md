# Bài 1: Tìm Đoạn Con K Phần Tử Có GCD Lớn Nhất

## Đề Bài

Cho dãy số nguyên $a_1, a_2, \ldots, a_n$. Tìm một đoạn con có đúng $k$ phần tử liên tiếp sao cho ước chung lớn nhất của $k$ phần tử này là lớn nhất.

**Dữ liệu vào:**
- Dòng đầu: $n, k$ ($2 \leq k \leq n \leq 10^3$)
- Dòng tiếp theo: $a_1, a_2, \ldots, a_n$ ($1 \leq a_i \leq 10^6$)

**Kết quả:**
- Giá trị lớn nhất của ước chung lớn nhất của $k$ phần tử liên tiếp

**Ví dụ:**
```
INPUT:
10 3
2 6 4 3 18 12 24 8 7 5

OUTPUT:
6
```

---

## Phân Tích Bài Toán

### Hiểu Đề Bài

Cho dãy: `[2, 6, 4, 3, 18, 12, 24, 8, 7, 5]`, $k = 3$

Các đoạn con 3 phần tử liên tiếp:
- `[2, 6, 4]` → $\gcd(2, 6, 4) = 2$
- `[6, 4, 3]` → $\gcd(6, 4, 3) = 1$
- `[4, 3, 18]` → $\gcd(4, 3, 18) = 1$
- `[3, 18, 12]` → $\gcd(3, 18, 12) = 3$
- `[18, 12, 24]` → $\gcd(18, 12, 24) = 6$ **(MAX)**
- `[12, 24, 8]` → $\gcd(12, 24, 8) = 4$
- `[24, 8, 7]` → $\gcd(24, 8, 7) = 1$
- `[8, 7, 5]` → $\gcd(8, 7, 5) = 1$

Đáp án: **6**

---

## Approach 1: Brute Force - Ý Tưởng Đơn Giản Nhất

### Ý Tưởng

Ta bắt đầu với ý tưởng đơn giản nhất để thể hiện tư duy logic:

1. **Liệt kê tất cả các đoạn con:** Có $n - k + 1$ đoạn con $k$ phần tử liên tiếp
2. **Tính GCD cho mỗi đoạn:** Sử dụng thuật toán Euclid
3. **Lưu GCD lớn nhất:** So sánh và cập nhật kết quả

### Phân Tích Độ Phức Tạp

**Time Complexity:** $O(n \times k \times \log(\max(a_i)))$

- Số đoạn con: $n - k + 1 \approx O(n)$
- Tính GCD của $k$ số: $O(k \times \log(\max(a_i)))$
  - Mỗi phép GCD: $O(\log(\max(a_i)))$
  - Cần $k - 1$ phép GCD

**Space Complexity:** $O(1)$

### Đánh Giá

Với ràng buộc $n \leq 1000$, $k \leq 1000$, $a_i \leq 10^6$:
- $O(1000 \times 1000 \times 20) \approx 20,000,000$ operations
- **Kết luận:** Hoàn toàn chấp nhận được!

### Code Implementation

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// Thuật toán Euclid để tính GCD
// Time: O(log(min(a, b)))
int gcd(int a, int b) {
    while (b != 0) {
        int temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}

// Tính GCD của k phần tử liên tiếp từ vị trí start
// Time: O(k * log(max_a))
int gcdOfSegment(int arr[], int start, int k) {
    int result = arr[start];
    for (int i = start + 1; i < start + k; i++) {
        result = gcd(result, arr[i]);
    }
    return result;
}

// Solution 1: Brute Force
int solution1_bruteforce(int arr[], int n, int k) {
    int maxGCD = 0;
    
    // Duyệt qua tất cả các đoạn con k phần tử
    for (int i = 0; i <= n - k; i++) {
        int currentGCD = gcdOfSegment(arr, i, k);
        maxGCD = max(maxGCD, currentGCD);
    }
    
    return maxGCD;
}
```

## Approach 2: Optimized với Early Stopping

### Quan Sát Quan Trọng

1. **Nếu GCD = 1:** Không thể nhỏ hơn nữa, có thể skip sớm trong quá trình tính
2. **GCD không thể vượt quá:** Giá trị lớn nhất trong dãy
3. **Early stopping:** Nếu đã tìm được GCD = $\max(a_i)$, không cần tìm nữa

### Cải Tiến

```cpp
int solution2_optimized(int arr[], int n, int k) {
    int maxGCD = 0;
    
    // Tìm giá trị lớn nhất trong dãy
    int maxValue = 0;
    for (int i = 0; i < n; i++) {
        maxValue = max(maxValue, arr[i]);
    }
    
    // Duyệt qua tất cả các đoạn con
    for (int i = 0; i <= n - k; i++) {
        // Tính GCD với early break khi = 1
        int currentGCD = arr[i];
        for (int j = i + 1; j < i + k; j++) {
            currentGCD = gcd(currentGCD, arr[j]);
            if (currentGCD == 1) break; // Early stopping
        }
        
        maxGCD = max(maxGCD, currentGCD);
        
        // Nếu đã đạt max có thể, return ngay
        if (maxGCD == maxValue) {
            return maxGCD;
        }
    }
    
    return maxGCD;
}
```

### Phân Tích

**Time Complexity:** 
- Worst case: vẫn $O(n \times k \times \log(\max(a_i)))$
- Average case: Tốt hơn đáng kể nhờ early stopping

**Space Complexity:** $O(1)$

## Approach 3: Liệu Có Thể Dùng Sliding Window?

### Phân Tích

Khi interviewer hỏi về sliding window (technique phổ biến với bài "đoạn con k phần tử"):

**Tại sao KHÔNG hiệu quả:**

1. **GCD không có tính chất cộng dồn:**
   - Sum: `sum[i+1] = sum[i] - arr[i] + arr[i+k]` (OK)
   - GCD: Không thể tính tương tự (Không OK)

2. **Khi slide window:**
   - Thêm 1 phần tử vào: `new_gcd = gcd(old_gcd, new_element)` (OK)
   - Bỏ 1 phần tử ra: Phải tính lại toàn bộ GCD từ đầu (Không OK)

3. **Cấu trúc dữ liệu phức tạp:**
   - Có thể dùng Segment Tree với GCD query: $O(n \log n)$ preprocessing
   - Nhưng với $n \leq 1000$, không cần thiết!

**Kết luận:** Brute force với early stopping là optimal cho bài này.

## Solution Cuối Cùng

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int gcd(int a, int b) {
    while (b != 0) {
        int temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}

int main() {
    int n, k;
    cin >> n >> k;
    
    int arr[1000];
    for (int i = 0; i < n; i++) {
        cin >> arr[i];
    }
    
    int maxGCD = 0;
    int maxValue = 0;
    
    // Tìm max value
    for (int i = 0; i < n; i++) {
        maxValue = max(maxValue, arr[i]);
    }
    
    // Duyệt qua tất cả đoạn con k phần tử
    for (int i = 0; i <= n - k; i++) {
        int currentGCD = arr[i];
        
        // Tính GCD của đoạn hiện tại
        for (int j = i + 1; j < i + k; j++) {
            currentGCD = gcd(currentGCD, arr[j]);
            if (currentGCD == 1) break; // Không thể nhỏ hơn
        }
        
        maxGCD = max(maxGCD, currentGCD);
        
        // Early stopping
        if (maxGCD == maxValue) {
            break;
        }
    }
    
    cout << maxGCD << endl;
    
    return 0;
}
```

### Câu Hỏi Mở Rộng Có Thể Gặp

**Q: Nếu $n = 10^6$ thì sao?**
- A: Cần Segment Tree hoặc Sparse Table cho GCD query: $O(n \log n)$ + $O(\log n)$ per query

**Q: Nếu cần tìm vị trí đoạn con, không chỉ GCD?**
- A: Lưu thêm biến `bestIndex`, return `(maxGCD, bestIndex)`

**Q: Có thể precompute gì không?**
- A: Có thể precompute GCD prefixes, nhưng vẫn cần $O(k)$ để tính GCD đoạn con
